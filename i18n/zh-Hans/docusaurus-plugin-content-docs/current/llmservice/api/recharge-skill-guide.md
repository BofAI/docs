# 充值 Skill 使用指南

`bai-recharge` 是指导 Agent 使用[充值 API](./recharges.md)的操作说明。你可以用自然语言表达充值需求，由 Agent 查询渠道、创建订单、提供收银台链接，并跟踪支付结果，无需自己编写接口请求。

**Skill 本身不提供钱包、API Key 或付款能力。** 能否执行相应步骤，取决于你使用的 Agent、网络访问权限及已配置的工具。它不是另一套充值系统，也不表示已内置到所有 B.AI 客户端。

## 开始前准备

| 准备项 | 说明 |
| --- | --- |
| 支持加载 Skill 的 Agent | 能读取 `SKILL.md`，并具备发送 HTTP 请求的工具。 |
| B.AI API Key | 在 [API Key 页面](https://chat.b.ai/key)获取，通过客户端支持的安全配置或秘密管理机制提供。 |
| 充值服务地址 | `https://chat.b.ai`；其他环境使用接入方提供的地址，不包含 `/v1`，不是模型接口地址 `https://api.b.ai`。 |
| 充值需求 | 明确到账对象、付款链、币种和数量；其他个人需邮箱或钱包标识，团队需 team slug。 |
| 钱包工具，可选 | 仅直接转账需要对应链的钱包消息签名和付款能力；没有这些工具时可通过收银台由用户付款。 |

金额单位是代币数量，不是美元或积分。可用链、币种、最低数量及最低美元价值，以实时查询结果为准。

## 1. 下载并加载 Skill

下载<a href="pathname:///downloads/recharge/bai-recharge/SKILL.md" autoAddBaseUrl={false} download="SKILL.md" target="_self">bai-recharge 的 SKILL.md</a>，按所用 Agent 的 Skill 安装或导入方式加载。支持目录式 Skill 的客户端，保持以下结构：

```text
bai-recharge/
└── SKILL.md
```

客户端的安装目录和加载方式可能不同，请以对应客户端说明为准。不要把 `SKILL.md` 当作可执行脚本；它需要由具备工具能力的 Agent 读取和使用。

加载后可以先发送一个不创建订单、不付款的检查请求：

```text
请使用 bai-recharge，检查是否能读取安全配置中的 B.AI API Key，
并查询当前支持的充值链、币种和最低金额。
不要显示 Key，不创建订单，不签名或付款。
如果缺少网络工具、配置或权限，请告诉我缺少什么。
```

## 2. 配置连接信息

向 Agent 提供充值服务地址，并通过客户端的安全配置提供 API Key。Skill 不要求某个固定的环境变量名称，按你的接入环境配置即可。

```text
充值服务地址：https://chat.b.ai
API Key：已通过当前客户端的安全配置提供，请勿显示或保存到生成的代码中。
```

不要将真实 Key、私钥或助记词粘贴到聊天、示例代码、截图或共享配置中。Skill 不需要取得钱包私钥；消息签名由已有的钱包工具完成。

## 3. 用自然语言表达需求

### 给当前账户充值

```text
请使用 bai-recharge，为当前 B.AI API Key 所属账户充值 10 USDC，
使用 Base 网络，走收银台，由我完成付款。
先查询实时充值选项并确认需求；缺少条件时告诉我，不要自动换链、换币或增加金额。
```

### 给其他个人或团队充值

```text
请给 person@example.com 对应的 B.AI 个人账户充值 10 USDC，
使用 Base 网络并提供收银台链接，由我付款。
```

```text
请给 team slug 为 your-team-slug 的 B.AI 团队充值 10 USDC，
使用 Base 网络并提供收银台链接，由我付款。
```

邮箱、team slug、链、币种和数量均为示例，请替换为本次实际需求。不要提供团队展示名称代替 team slug；目标不明确时应先确认，不要默认充入自己的账户。

## 4. 确认订单并完成付款

Agent 会先查询实时选项，创建订单后按照返回的 `next_action` 处理：

| 流程 | Agent 与用户分别做什么 |
| --- | --- |
| 收银台 `cashier` | Agent 提供本次订单的完整收银台链接，用户在页面完成钱包绑定及付款，收银台处理交易上报。Agent 后续查询原订单。 |
| 直接转账 `direct-transfer` | 需要有效的钱包归属签名、对应的钱包工具和付款授权。核对原订单后，用绑定的钱包支付准确数量，保存真实交易 hash，再上报及查询结果。 |

提供了付款地址但无法签名时，Agent 应说明缺少签名能力，不会擅自删除地址切换流程。若你希望改走收银台，请先明确新的处理方式；已有或结果不明确的订单应先核查。

**同意查询或建单，不等于授权自动付款。** 涉及签名和转账时，仍需遵循所用 Agent 与钱包工具的安全确认流程。付款前核对到账对象、链、代币、准确数量和收款地址；网络手续费另计。

## 5. 查看结果或继续原任务

| Agent 报告的结果 | 含义 |
| --- | --- |
| 待收银台操作 | 订单已创建，仍需你打开链接完成付款。 |
| `pending` | 支付尚未确认，保留原订单及已有交易 hash，稍后查询。 |
| `paid` | 支付已确认，但不表示积分已到账；积分异步处理。 |
| `expired` / 结果待确认 | 停止付款，保留订单信息并核查，不自动再次支付。 |

遇到中断时，向 Agent 提供原业务订单号：

```text
请查询 out_trade_no 为 <原业务订单号> 的充值状态。
保留原订单和已有交易，不重新建单或付款，也不要更换交易 hash。
告诉我当前状态，以及仍需我完成的下一步。
```

Agent 应交付业务订单号 `out_trade_no`、平台订单号 `order_id`（如有）、实际支付状态、链/币种/数量及真实交易 hash（如有）。收银台链接含会话凭证，仅交付本次付款用户，不要公开分享。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 下载 Skill 后仍不能充值 | 检查 Agent 是否已加载文件，是否有 HTTP 工具、网络权限和安全配置中的 Key。下载文件本身不会新增这些能力。 |
| 没有钱包工具 | 选择由用户完成的收银台流程，不宣称可以自动签名或转账。 |
| 创建订单超时或提示订单号重复 | 用原 `out_trade_no` 查询，确认结果后继续原单，不用新订单号绕过。 |
| 收银台链接丢失 | 查询接口不会补发链接；保留原订单交由接入方处理，不重复付款。 |
| 已付款但仍为 `pending` | 核查原交易和原订单，稍后继续查询，不重新发送交易。 |
| 状态为 `paid` 但积分页面未更新 | `paid` 只确认支付，不能据此宣称积分已到账。 |
