### 代理钱包与配置修正

<div className="changelog-tags"><span className="changelog-tag">文档</span><span className="changelog-tag">修复</span></div>

- **`setWallet()`**——四处示例给出了四种不同的调用形态。它们各自单看都合法，但彼此不一致会让人以为这个 API 不稳定，而且只传一个参数的示例没有写明其成立条件。现已统一为每种语言一种形态（TypeScript 为 `setWallet(newWallet, options)`，Python 为 `setWallet(new_wallet, chainId=None, *, new_wallet_signer=None, deadline=None, signature=None)`），并补上了那个缺失的前提：对一个*与所有者不同*的钱包直接调用 `setWallet(address)` 会抛出 `New wallet must sign`。只有当 SDK signer 本身就是新钱包时 SDK 才会自动签名；否则必须传入 `new_wallet_signer` / `newWalletSigner`，或为智能合约钱包提供现成的 `signature`。
- **签名到底覆盖了什么**——新增「签名从何而来」一节，说明三条签名路径各自的适用场景。「我到底要签署什么？」中的字段也补齐了真实约束：`deadline` 默认为 60 秒后、合约上限为 **5 分钟**，EIP-712 域为 `ERC8004IdentityRegistry` 版本 `1`，并且智能合约钱包可通过 [ERC-1271](https://eips.ethereum.org/EIPS/eip-1271) 的 `isValidSignature` 回退路径获得支持（此前只描述了 EOA）。同时补充说明 `agentWallet` 是保留键，`setMetadata()` 与 `register()` 都会拒绝它。
- **TRON 的 `chainId`**——`chainId=1` 属于旧版兼容字段，所有 TRON 初始化示例中都已移除。不传它，Nile 才会生成当前的 `3448148188:<tokenId>` 形式的 agent ID。EVM 示例保留各自真实的链 ID。
- **TRON 网络标识**——网络表与全部示例改用裸名称（`mainnet` / `nile` / `shasta`）。两个 SDK 仍然接受 `tron:nile` 这类带前缀的别名并在内部去掉前缀，因此既有代码不受影响；注意这是 SDK 自身的别名，与 x402 使用的 CAIP-2 标识分属不同命名空间。
- **注册文件的键名**——自托管文件示例此前用的是 `endpoints` 与 `x402support`。registration-v1 的线格式——即 Python 的 `to_dict()` 所输出、也是 SDK 自带 fixture 采用的格式——是 `services` 与 `x402Support`，示例已据此订正。TypeScript 是例外，见下一条。
- **读取已加载的 Agent（TypeScript）**——示例打印的是 `loaded.registrationFile.name`，但 `registrationFile` 在 `Agent` 类上是 `private readonly`，这一行根本无法编译。现已改用公开的 `loaded.toJSON().name`。Python 不受影响：它的 `registration_file` 是公开属性。8004 与 x402 指南中每一个完整的 TypeScript 示例，都已对照已发布的包在 `strict` 模式下做过类型检查。
- **文档对应的是哪个发布版** — 特性矩阵现在写明 npm 上的发布版本（`@bankofai/8004-sdk` 1.1.2），并说明 Python 包未发布到 PyPI。同时记录了两个语言的一处差异：Python 的 `to_dict()` 输出 registration-v1 的线格式键名（`services`、`x402Support`），而 TypeScript 发布的是其内部键名（`endpoints`、`x402support`），因此 TypeScript 调用方在自行托管文件前需要先做转换。Python 的安装命令现已固定到 `main`（`git+…@main`、`git clone -b main`）——该仓库的默认分支是 `develop`，不指定分支会拉到尚未发布的代码。
- **OASF slug 存在哪里**——文档此前称技能与领域存放在 `endpoints` 数组中。实际 Python 会在 `services` 里构建一个 `OASF` 条目，而 TypeScript 是把 slug 推入顶层扁平的 `tags` 数组，并额外输出 Python 文件中并不存在的 `tags` 与 `metadata`。两种表示现已分别写明。
- **私钥**——示例改为从 `TRON_PRIVATE_KEY` / `EVM_PRIVATE_KEY` 环境变量读取，不再内联明文；原先引用未定义变量的示例现已可直接运行。另修正了一个只有 39 位、格式非法的示例地址。
- **OASF 技能与领域 slug**——示例中使用的是分类表里并不存在的两级 slug（`technology/data_science`、`natural_language_processing/summarization`），其中数处还搭配了 `validate_oasf=True`，会直接抛错。文档中的每一个 slug 都已用 SDK 自带的 `validate_skill()` / `validate_domain()` 对照内置分类表（136 个技能、204 个领域）实际跑过校验；无效的已改为分类表真正定义的三级形式。那些刻意搭配 `validate_oasf=False` 的 `custom_skill/...` 示例保持不变。此外注册文件示例中 OASF 条目自身的 `version` 也写错了——写成了 `v0.8.0`，而 SDK 实际写入的是 `0.8`，即 8004 规范示例采用的取值。
- **新增：SDK 特性矩阵**——用一页列出两个语言实现各自真正支持的能力，内容取自 SDK 源码。它补上了此前完全没有文档的信誉、验证、所有权/操作员与发现类 API，并记录了两者之间的差异——其中最重要的是**验证注册表 API 仅 TypeScript 有实现**。
