# x402 Payment Protocol

Release notes for the x402 protocol, SDK, and [CLI](/x402/cli/).

<div className="changelog-entry">
<div className="changelog-date">Sep 9, 2026</div>

### Docs audited against the source repositories

<div className="changelog-tags"><span className="changelog-tag">Docs</span><span className="changelog-tag">Fix</span></div>

- **API Catalog examples rebuilt from the real provider** — the `catalog.json` and `pay.md` samples now match `providers/sunpump-token-launch/`: three chains and four routes, including TRON `exact_gasfree` and the Base `eip3009` route. The previous samples omitted `assetTransferMethod` and would have failed schema validation if copied. The submission checklist now states when the field is required, when it must be omitted, and that one network may carry several routes.
- **Settlement record de-duplication** — the facilitator page claimed successful settlements were de-duplicated per authorization identity. They are not: `/settle` inserts one row per attempt, the table carries no unique constraint, and there is no upsert or pre-check. At most one success exists per identity only because on-chain replay protection allows a single settlement. The `/payments` feed's `limit` (default `50`, capped at `200`) and `offset` defaults are now documented, along with the `not_found` / `invalid_identity_query` / `missing_identity_or_auth` error codes.
- **Field corrections** — `subTitle` is not a valid provider field and has been removed (the schema rejects unknown keys; only `subtitle` exists), along with the `sub_title` derivation note that referenced it. Base Sepolia is flagged as schema-level only: the build ships no display metadata for it.
- **Payload accuracy** — transfer authorization is carried in `payload.authorization` on the EIP-3009 path and `payload.permit2Authorization` on the Permit2 path. `extra` may carry `name`/`version` for permit2 assets that also implement EIP-2612 — the client's signal to sign a gasless permit instead of broadcasting `approve`.
- **Scoped claims** — balance-aware payment selection and the cheapest-token strategy are TRON-only; `HTTPFacilitatorClient` retries rate limits on `getSupported()` only, while `verify()` and `settle()` surface a 429. TRON Shasta was added to the protocol network list.
- **Payment record queries** — corrected the anonymous access description: the `tx_hash` and `network` + `nonce` lookups apply no seller filter without an API Key, so anyone holding an exact identifier can resolve the record. There is no unauthenticated listing endpoint, but these lookups are not rate-limited either (the official service's anonymous limit of 1 request per IP per minute covers `/settle` only) and settlement tx hashes are public on-chain data, so settlement metadata is effectively public rather than seller-private. The page now flags this as current implementation behaviour, not a recommended access-control policy.
- **Facilitator** — removed a stale reference to facilitator fees. EVM ERC-20 approval gas sponsoring is now documented with its real conditions: the SDK does not register it automatically, a self-hosted facilitator must opt in, the official facilitator registers it for BSC and Base, and the resource server must declare the extension on the route.
- **CLI reference** — `/health` and `/.well-known/x402` accept any method, and the latter also returns `rawAmount` and `pay_url`; documented the `--providers-dir` and `--query` aliases, the default positional for `catalog build`, and the default output directory for `export-gateway`.

### x402 SDK v1.2.0 — TRON approval resource sponsoring

<div className="changelog-tags"><span className="changelog-tag">New Release</span><span className="changelog-tag">SDK</span><span className="changelog-tag">TRON</span></div>

- **New `trc20ApprovalResourceSponsoring` extension** (wire-schema version `1`) for TRON `exact`, `upto`, and the Permit2 deposit/top-up path of `batch-settlement`. The payer signs `approve(Permit2, MaxUint256)` **without broadcasting it**; the facilitator strictly decodes the signed transaction, binds it to the selected payment, temporarily delegates the Stake 2.0 Energy — and, when needed, Bandwidth — that the payer lacks, broadcasts the unchanged transaction, and reclaims the delegation through a recoverable state machine. The payer therefore needs no TRX for that first approval. No new endpoint — the flow stays `402` → `PAYMENT-SIGNATURE` → `/verify` → `/settle`.
- **Facilitator sponsoring runtime** — Stake 2.0 resource sizing, bounded sponsorship policy, durable operation-coordinator contracts, crash recovery, and resource reclamation. The process-local `InMemoryTrc20SponsoringCoordinator` is for tests and development only; production needs a durable coordinator with scheduled reconciliation.
- **TRON client approval policy** — tokens now resolve a per-token approval-update strategy shared by the sponsored and self-funded paths: `zero-first` (the default for known Permit2 assets, which rejects a non-zero-but-insufficient allowance with `approval_reset_required`), opt-in `direct-overwrite`, and `unsupported` for unrecognized assets (`approval_asset_unsupported`). The SDK never inserts an implicit `approve(0)`.
- **Package set** — `@bankofai/x402-extensions` and `@bankofai/x402-tron` move to `1.2.0`; `@bankofai/x402-express`, `-fastify`, `-hono`, and `-next` to `1.1.1`; `@bankofai/x402-core`, `-evm`, `-fetch`, `-axios`, and `-mcp` stay at `1.1.0` because their APIs and dependency graphs did not change. Node.js 22+ is unchanged.
- The official facilitator does **not** currently enable this extension; TRON approval sponsoring requires a self-hosted facilitator with a resource-owner wallet.

### x402 SDK v1.1.0 — payment flows & wallet compatibility

<div className="changelog-tags"><span className="changelog-tag">New Release</span><span className="changelog-tag">SDK</span></div>

- **Payment flows are now explicit** — a scheme/network server declares the flows it supports per asset-transfer method. `upfront` and `escrow` travel on the wire as `extra.paymentFlow`; `authorization` stays the default and is omitted from `extra`. Legacy v1.0 servers that declare nothing keep using the authorization flow.
- **Client spend controls are on by default** — a client pays only assets it recognizes from the default-asset registry, capped at `DEFAULT_MAX_AMOUNT_PER_PAYMENT` (`$1` worth) per payment. Raise the cap with `spendControls.maxAmountPerPayment`, allow a custom token with `spendControls.allowedAssets`, or switch the guard off with `spendControls: false`.
- **Payment-selection policies and lifecycle hooks** — `PaymentPolicy` plus `onBeforePaymentCreation` / `onAfterPaymentCreation` / `onPaymentCreationFailure` / `onPaymentResponse`.
- **EVM wallet compatibility** — deployed smart accounts, ERC-7702 delegation, and allowlisted ERC-6492 counterfactual wallets. ERC-6492 requires an explicit `eip6492AllowedFactories` allowlist on the facilitator.
- **`HTTPFacilitatorClient`** gains typed timeout errors, rate-limit retries, stricter response validation, and a 90-second default timeout.
- Upgrade all **11 `@bankofai/x402-*` packages together** — internal dependencies resolve to `~1.1.0`. The SDK requires **Node.js 22+**. Custom money parsers now receive decimal strings.

### x402 CLI v1.0.2 — Base USDC & Agent Wallet

<div className="changelog-tags"><span className="changelog-tag">New Release</span><span className="changelog-tag">CLI</span><span className="changelog-tag">Base</span></div>

- **Base support** — `eip155:8453` (Mainnet) and `eip155:84532` (Sepolia), both with USDC, plus the `base-mainnet` / `base-sepolia` aliases. Base settles through the standard `exact` scheme using **EIP-3009** authorization rather than Permit2. Supply your own RPC in production via `--rpc-url` or `EVM_RPC_URL_8453` / `EVM_RPC_URL_84532`.
- **Agent Wallet is now the default payer** — `pay` resolves your active [Agent Wallet](/Agent-Wallet/Intro/) and delegates signing, so no private key sits in an environment variable. If wallets are configured but none is active, the CLI **stops before signing** instead of picking one for you. Select explicitly with `--wallet-id` / `AGENT_WALLET_ID`, or point at another directory with `AGENT_WALLET_DIR`. Private keys are now a development/CI override only.
- **Redirects are no longer followed** on paid requests, so `PAYMENT-SIGNATURE` can't be forwarded to another origin.
- **EVM balance pre-check** — the CLI verifies the payer's token balance before signing and returns the resolved wallet ID, address, and raw balance.
- New: `pay --asset` / `--decimals`, `serve --valid-for-seconds` (default `300`), and `roundtrip --json` emitting one document with separate `serve` and `pay` results.
- New wallet error codes: `WALLET_PASSWORD_REQUIRED`, `WALLET_DECRYPTION_FAILED`, `WALLET_CONFIG_CORRUPT`, `WALLET_NETWORK_ERROR`.

<div className="changelog-tags"><span className="changelog-tag">Update</span><span className="changelog-tag">Facilitator</span><span className="changelog-tag">Base</span></div>

### x402 CLI v1.0.0

<div className="changelog-tags"><span className="changelog-tag">New Release</span><span className="changelog-tag">CLI</span></div>

First stable release of `@bankofai/x402-cli` — a TypeScript command-line client for x402 payments.

- **`pay`** — pay any x402-protected URL: probe, read the `402` challenge, sign, and retry
- **`serve`** — run a local x402 paywall endpoint that verifies and settles through a facilitator
- **`roundtrip`** — start a temporary server, pay it, exit: the fastest end-to-end smoke test
- **`gateway`** / **`catalog`** — validate and scaffold provider files; search, cache, and export the provider catalog
- Built on the published `@bankofai/x402-core` / `x402-evm` / `x402-tron` SDK 1.0 packages; `scheme=exact` with Permit2
- Networks: TRON (`tron:mainnet` / `tron:nile` / `tron:shasta`) and BSC (`eip155:56` / `eip155:97`)

👉 Get started: [x402 CLI Quick Start](/x402/cli/quickstart/)
